# Hustudy 需求追踪与验收矩阵

作者：张昊轶｜项目：Hustudy。

本矩阵用于证明每项需求都能追溯到来源、设计任务和验收方法，服务课程评分中的“可验证性”“一致性”和“易追溯性”。

## 1. 来源编码

| 编码 | 来源 |
|---|---|
| U1 | 项目组已确认：4 人、名称 Hustudy、工具类 |
| U2 | 前序需求：学习闭环、PPT/PDF 学习、AI 辅助复习 |
| U3 | 前序需求：GitHub 学习效率项目融合、Codex 可实施 |
| U4 | 本轮明确需求：PPT/PDF/DOCX 资料库、重点难点考点讲解、笔记/资料/图片交叉引用、历年真题分析和模拟题 |
| C1 | 课程附件：需求分析内容、AI 协作记录、人工核实和个人提交 |
| D1 | 工程设计推导：可行性、结构化引用、异常处理、测试与隐私边界 |

## 4. 状态、输入输出和异常覆盖

| 业务对象 | 正常状态 | 失败/边界状态 | 关键测试 |
|---|---|---|---|
| ProcessingJob | QUEUED→RUNNING→SUCCEEDED | FAILED、CANCELLED、重试上限、worker 重启 | TC-03、TC-12 |
| DocumentVersion | PARSED→PREVIEWED/INDEXED | 扫描、加密、损坏、预览失败、引用失效 | TC-02–05、TC-26 |
| Note | 编辑→保存 revision | 409 并发冲突、图片失效、恶意 Markdown | TC-07–09、TC-23、TC-27 |
| PastQuestion | DRAFT→CONFIRMED | 跨页、子题、未知分值、无答案、不可识别图表 | TC-28 |
| Mapping | SUGGESTED→CONFIRMED/REJECTED | 别名、合并、课件未匹配、报告 STALE | TC-29–30 |
| ExamPaper | DRAFT→REVIEWED→READY | 蓝图冲突、来源不足、重复题、生成超时 | TC-13–14、TC-31 |
| ExamAttempt | IN_PROGRESS→SUBMITTED→SCORED | 刷新、断网、截止、重复提交 | TC-15–16 |
| ReviewTask | PENDING→COMPLETED/RESCHEDULED | 时区变化、来源删除、重复创建 | TC-17、TC-20 |
