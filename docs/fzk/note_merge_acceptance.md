# 笔记逐段合并与草稿保护

2026-10-26，fzk（Codex辅助）；分支 `codex/fzk-m3-safe-merge`，基线 `aa45665`。对应 C08/C09/C10 的保存冲突、健壮性与编辑体验。用户已反馈本人复验通过；原第9项跨课程和独立恢复继续暂缓。

## 使用

同一篇笔记在两个窗口修改，后保存的一方遇到409时，可点击「逐段合并」。不同位置的修改会组合到预览，相同修改只保留一份；同一段的不同修改须选择本地或服务端。标题、标签和文件夹也分别核对，避免合并正文时恢复旧分类。

「应用合并到草稿」先保留原本地草稿的独立恢复副本，再更新编辑器；此时暂停自动保存。继续编辑后点击「立即保存」。如果另一窗口在此期间再次保存，仍会出现409，不强制覆盖。取消合并保留原输入。

编辑区可下载当前草稿，冲突区可分别下载本地草稿和服务端版本，恢复列表可下载副本。下载为按标题安全命名的完整Markdown正文；保留原始图片/双链UUID，不携带图片附件，不等于可离线阅读的选择导出ZIP。

旧恢复副本缺少共同版本、任一正文超出20万UTF-16码元或1万行、差异超过200万个比较单元时，明确停止自动合并。全文仍可下载，原整篇核对入口保留；不会截断内容后伪装合并成功。

恢复存储不可用时，应用合并或载入服务端会停止，以免替换未备份的正文；「核对后保留本地草稿」仍可使用，因为它保持当前正文不变，随后可明确保存。若选择后的结果已与服务端完全一致，显示无需保存并保留原本地副本。

## 实现与边界

| 部分 | 实现 |
|---|---|
| 共同版本 | 编辑器最后确认的Note正文与revision；恢复副本新增可选base，旧记录兼容，不把新服务端正文当作旧基线 |
| 差异算法 | 保留行终止符的逐行比较，剔除共同前后缀，再用有界LCS提取区间修改；按原文区间归并，重叠修改显式选择 |
| 复杂度 | 对两组变化区间共用200万矩阵单元预算；矩阵单元4字节。区间排序后线性扫描，文本分块一次拼接；不反复复制累积正文 |
| Markdown保真 | 中文、公式、UUID引用、CRLF/LF/CR、末行无换行均按原始字符串保留，不自动格式化 |
| 数据组织 | 无新数据库表、迁移或依赖。继续使用FastAPI/SQLite原Note接口及revision乐观锁；三方比较只在浏览器TypeScript中运行 |
| 安全显示 | 差异和预览为React纯文本，不执行Markdown里的HTML，不请求外链或模型；下载沿用标题文件名清洗 |
| 草稿保护 | 应用前保存独立副本；1 MiB单份、3 MiB总量、20份、30天原限制保持，base计入预算；写入失败阻止替换并提示下载 |
| 状态保护 | 比较冻结本地/服务端快照，应用前复核当前笔记和输入；再次409继续核对；401关闭合并窗口，保留编辑器草稿 |

本轮范围是同一账户多个窗口的冲突核对，不提供实时多人协作。M2/资料阅读中的独立笔记创建流程保持原接口。

## 手动复验

1. 新建「合并练习」，输入三段文字并保存。在两个窗口打开同一篇笔记。
2. A窗口修改第一段并保存；B窗口修改第三段。B出现冲突后点击「逐段合并」，确认预览同时包含两处修改。
3. 应用后等3秒，A刷新仍只有A的修改；B点击「立即保存」后，A刷新看到合并结果。本机恢复列表应仍有B合并前的草稿。
4. 两窗口重新打开同一版本，分别修改同一段；逐项选择本地或服务端，再应用。取消一次应保留原草稿，重新打开重新选择。
5. 两窗口分别修改标题、标签或文件夹，确认双改字段逐项核对，只有一方修改的字段自动保留该方修改。
6. 合并应用后、保存前，再由另一窗口保存新修改；当前窗口保存应再次提示冲突，新修改不得消失。
7. 分别下载两份冲突正文，检查标题命名、中文/公式/完整末段；在390px窄屏检查弹窗操作与横向溢出。
