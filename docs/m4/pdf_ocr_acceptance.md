# 扫描PDF题库图片转文字（2026-10-20）

本轮补充PDF没有文字层的情况。普通PDF不能靠文本模型直接识别图片：先在本机渲染原页并做OCR，再解析成题库草稿；AI知识点语义归类仍是后续独立入口。

## 使用

1. 在“本地直接上传（PDF / ZIP）”选择文件。ZIP内PDF按同一流程处理。
2. 系统逐页检测文字层，无文字/文字极少的页会提示页号，包含大图且只有少量文字的页也会提示。扫描和混合PDF不会先导入半份题目。
3. 点击“识别扫描页并拆分题目”：有正常文字层的页沿用原文，扫描页转图片后本地OCR，按页序合并。单栏/双栏可选；跨页题目沿用原有拆题逻辑。
4. 文字层损坏或检测遗漏时，可显式点击“整份PDF转图识别（文字层异常时）”。普通文字PDF导入完成后也提供此选项。
5. 完成后自动显示题目，对照原页核对答案、公式和图中文字。页面原图仅供审核；需要给题目配插图时再裁取并确认，原图不会自动进入作答页。

## 边界

- 单批PDF最多20页、32MiB、24万字；单页渲染最多2000万像素、图片10MiB、所有渲染图128MiB。检测子进程30秒、转图120秒、OCR子进程360秒，总任务租约480秒；超限或失败明确提示，不伪造题目。
- 文字层是否正常采用启发式检测，不等于能判断所有乱码/隐藏文字。每份有效PDF均保留整份强制OCR选项。空白页可能同样被提示为待识别；全空识别结果失败，不生成空题。
- OCR为本机RapidOCR，PDF渲染复用已锁定pypdfium2 4.30.0，纳入backend/requirements-bank-ocr.lock；无远程调用/运行时模型下载。安装组件后需重启API和worker。
- 复用BANK_OCR持久任务，明确点击后才运行。网络重复提交同请求不重复任务；重试必须显式触发。处理中断/租约失效/来源撤销拒绝迟到题目写入。
- M1版本、切片、parse_status/index_status均不回写。原页图片通过M1 Asset存储并关联版本/页号，删除资料后原页不可读取，派生题目不再可抽取；旧作答保留。
- 上传队列和图片识别任务中可查看结果及原页；完成时检测未保存校正草稿，避免自动刷新覆盖。

## 验证

自制 `fixtures/question_bank_scan_demo.pdf` 为纯图像；`question_bank_mixed_demo.pdf` 为同一图像页加一页真实文字层，生成脚本为scripts/create_bank_pdf_fixtures.py，不包含私人材料。两份样例均用Poppler渲染并检查了原图清晰度和文字页。

后端新增9项测试，实际运行PDFium和RapidOCR识别混合样例，得到两道扫描题加一道文字题；核对选择题四选项和正确答案B、正常文字页不重复、M1解析状态不变、原图版本/页号、幂等、跨账户拒绝、强制OCR、来源撤销、加密/页数预算、空白失败、备份恢复以及删除来源后不可抽题/开始新作答。最终相关回归75项通过，包含这9项及既有PDF/ZIP/图片/AI分类/作答/统计。

Chromium浏览器最终6项通过：纯扫描PDF及ZIP内混合PDF实际OCR，确认前没有任务/题目，确认后自动显示2/3题，并验证390px无溢出；其余4项回归文字PDF/ZIP和用户原PDF。前端58项单测、TypeScript、Ruff、生产构建、pip check通过。真实手写、复杂公式、低清扫描准确率仍需人工核对，不把自制清晰样例当作任意PDF质量保证。
