# M2 第二轮：格式修复与执行预算验收（2026-10-24）

本轮完成可独立推进的 FR20 有界结构修复与 FR45 实际执行预算，只修改 `Hustudy-gcx3`。`Hustudy-main-1024` 保留为历史副本。AGENTS、契约、README、用户手册、API 与 gcx 协作记录已同步；没有新增数据库表、迁移、依赖或隔离环境，没有读取密钥或自动发送真实模型请求。

## 实现内容和边界

1. **格式修复由用户选择。** 默认关闭；界面可授权最多 2 次，接口支持严格整数 0/1/2。只有 JSON 或结构字段不合要求、且有不超过 16000 字符的安全原响应时，才允许追加格式修复请求。原失败内容仅在内存中随修复发送，不保存到数据库、日志或错误详情。修复可能增加费用，预览与发送确认均说明。
2. **引用仍须核实。** 已有引用字段格式错误、引用编号不存在、摘录不符合原文，不通过结构修复绕过。限流、鉴权、网络失败、超时、输出截断、疑似密钥回显等也不会自动再发。没有安全原响应时直接停止。
3. **每次确认对应 120 秒处理窗口。** 从首次实际派发起，原始生成、格式修复、网络等待和报告跨批排队共用窗口；首次派发前排队不计时。网络读取受可取消的绝对截止时间约束，不仅检查单次读取是否超时。另按待处理批次和授权修复次数限制调用数、输入字符和输出 token 预留量。
4. **保留报告进度。** 预算到期停止，已完成报告批次保留，不冒充全文完成。用户重新勾选同意、明确续跑后，开启新的 120 秒窗口，跳过成功批次；整个报告累计格式修复次数仍不超过原授权，续跑不会补满修复额度。问答失败可重新预览并确认新的请求。
5. **显示真实执行状态。** 预览、处理中和结果显示调用数、修复使用数及当前窗口。每次追加调用前复核来源、归属、模型/密钥配置、任务租约和取消状态。内部执行记录不出现在正常问答历史或学习记录统计中；复用旧结果保留当时的执行快照，不触发新调用。

处理窗口不是整篇长课程必在两分钟内完成的承诺。模型成功返回合法答案时，即使授权 2 次修复，实际修复数仍应为 0。提供商失败请求未必返回 token 统计，界面的已知 usage 不能当作所有调用的完整账单。

M4 题库识别/抽题和 API 连接探测没有启用本策略，已停用的 AI 出题没有恢复。教师/历年题来源区分、审阅笔记补充输入需要后续跨模块协作；个人 API 接入方案仍待小组决策。

## 使用前重启

本轮修改了后端和 worker 代码，**请先重启后端**。默认由后端托管的 worker 会一起加载；不另开第三个 worker 终端。若你手动关闭了自动托管并单独运行 worker，则也需重启该 worker。前端开发服务器通常自动更新，浏览器按 Ctrl+F5 刷新即可；不需要重新安装依赖。

在原后端终端按 Ctrl+C，然后执行普通版本：

```powershell
Set-Location 'E:\aa大学\大三上\软件工程\Hustudy\Hustudy-gcx3'
$env:PYTHONUTF8 = "1"
python -m uvicorn app.main:app --app-dir backend --reload --reload-dir backend/app
```

如果普通 `python` 没有指向已安装依赖的解释器，最后一行改为：

```powershell
& 'E:\Anaconda\python.exe' -m uvicorn app.main:app --app-dir backend --reload --reload-dir backend/app
```

若前端也已关闭，在另一个终端执行：

```powershell
Set-Location 'E:\aa大学\大三上\软件工程\Hustudy\Hustudy-gcx3'
npm run dev --prefix frontend
```

打开前端终端显示的 Local 地址，通常是 `http://localhost:5173/`。

## 网页人工测试

建议新建一个测试课程，上传仓库自制的 `fixtures/learning_loop_material.md`，也可使用自己的 PDF/PPTX。先在资料阅读中核对提取正文；扫描图片、复杂公式等缺失不能当作模型已经阅读。以下真实发送使用你已配置的 API，可能产生费用。

### 1. 默认不修复

进入“资料问答”，选择资料，提问“流量控制与拥塞控制有什么区别？”。保持“允许最多2次格式修复”未勾选，点击预览。应看到未授权修复、120 秒窗口；预览本身不调用模型。

核对片段后勾选发送同意并确认。正常回答应显示已调用 1 次、已用格式修复 0/0 次，来源可回原文。若模型返回格式错误，应停止，不自动增加调用。

### 2. 明确授权修复

在发送预览前勾选“允许最多2次格式修复（可能增加AI调用费用）”，重新预览。问答本次调用上限应为 3 次，修复额度为 2，并要求确认。

正常结果显示 1 次调用、0/2 次修复是正确行为。只有自然发生可修复的格式错误，才可能显示 2 或 3 次调用。引用失败、1305 限流或鉴权失败应停止，不消耗修复机会。**不要通过反复请求或在课件中写入诱导指令来制造错误；确定性异常用下面的离线测试验证。**

### 3. 多批报告与续跑

进入“学习报告”，选择较长课件，核对预览中的实际批次与片段。确认后各批共用当前处理窗口；若正常完成，完整报告可阅读、回源和复用。

若处理超过预算，应明确显示“处理预算已用尽”，已完成部分保留且不标成完整报告。重新勾选同意后点击续跑：窗口编号递增，已成功批次不重发，累计格式修复次数不清零。小样本或模型很快时不会触发预算到期，属正常现象。

### 4. 取消和历史

仅在可丢弃的测试课程中尝试取消处理中任务。取消后不得追加修复或写入迟到成功结果；已经发往提供商的请求不能撤回。重新打开已有结果应展示原执行统计，不自动调用模型；学习记录中不能出现名为 execution 的内部条目。
