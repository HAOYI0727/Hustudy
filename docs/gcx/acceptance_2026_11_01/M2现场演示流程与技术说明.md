# M2现场演示与验收流程（第三轮，2026-11-01）

适用版本：Hustudy-main-1031。对应老师的功能展示、非功能性展示、关键技术和主体代码量四个维度。本文是演示设计，不是已执行或已通过的测试记录；统一课程资料待团队确定。不会自动上传材料、调用模型或修改日常账户。

## 一、演示目标与范围

用一条连续的学习过程演示：原文检索 → 带引用问答 → 核对原文 → 学习报告 → 标签审阅与笔记草稿 → 明确保存 → 复用成功结果。以数据库课程为首选方向，具体名称和知识点等团队确认资料后再填；操作系统、计网可沿用同一流程。

M2当前独立入口是“资料原文检索、资料问答、学习报告”。不演示已停用的独立AI出题；题库导入、练习与评分归M4。原文解析/阅读归M1，笔记保存归M3，模型配置为跨模块共享集成，讲解时说明协作边界。

教师强调入口按用户决定暂缓：没有合法标记时显示AI建议，不将其包装成已完成的真实功能。已确认真题的上游入口现已补齐，单独作为跨模块扩展案例，准备成功后才纳入主讲。

## 二、资料未定时的准备条件

| 材料代号 | 需要的内容 | 用途 |
|---|---|---|
| M-短课件 | 一段完整的小节，正文明确含一个概念、两个概念的区别及一个例子；优先文字清晰的PDF/PPTX | 问答、报告和引用主案例 |
| M-长课件 | 可提取正文超过8000字符且在400原片段/24万字符内；准备一个需要后部内容，或前后两个章节共同支持的问题 | 分批问答与覆盖展示 |
| N-个人笔记 | 少量人工检查过的总结，与M-短课件同课程；内容不与原文冲突 | 选中并确认后作为补充 |
| Q-真题 | 一份可明确说明来源、已核验且有课件知识点关联的题库 | 可选的已确认真题标签联调 |

选好资料后，先在资料库核对解析/索引完成，检查预览的实际正文、末页关键定义、表格与公式是否可读。选中课件不等于扫描图片已转为正文；扫描件或复杂公式提取不足时应更换主案例或显式补录核对，不把缺失材料当模型问题。

如果最后统一数据库资料，可按实际内容选择“主键和外键”“事务ACID”“索引适用条件”等问题，不能假设统一资料一定含这些内容。提前写下答案要点和原文页码/片段，以实际资料为准。

## 三、演示前一次性准备

1. 在固定的1031目录启动前后端，确认worker可处理任务，避免混用旧项目数据库或重复worker。
2. 使用专用演示账户A创建课程、上传资料并核对正文。准备一个普通账户B，用于展示账户级API隔离；B是否无密钥须提前检查，不能在现场猜测。
3. A保存本人可用模型配置，提前人工验证连接与结构化输出。连接测试和生成都可能消耗额度，按本人确认执行；不要反复点击。密钥输入过程不投屏，截图不含真实密钥。
4. 准备一个短问答及一个学习报告的成功历史，另准备未用过的同章节问题供现场调用。相同输入若有可复用结果，主案例可明确选择重新生成，也可把复用留作后续演示。
5. 在同一资料/模型配置下排练一次，把问题、预期答案、实际耗时、引用位置和截图记入演示备忘。不要把自动测试替身响应当真实模型质量证据。
6. 先准备报告历史再开始演示。取消、换模型、删除来源等破坏当前预览的案例最后进行；如演示改配置，应重新预览，不能继续使用旧授权。

## 四、建议主流程：约10–12分钟

时间是人工讲解安排，不是接口响应承诺。真实生成超出等待时间时，明确切换到之前排练的已保存结果，展示同一流程，不冒充当前请求已经完成。

| 步骤/时间 | 具体操作 | 现场核对点 | 讲解与截图 |
|---|---|---|---|
| D01 课程与范围，约1分钟 | 打开课程与AI学习，说明已上传的统一资料，切“资料原文检索”，输入课件确实存在的术语 | 返回原文与来源，点击能打开正确版本/位置；本步骤不调用AI | 截图S01：检索与来源。讲解“先核对资料，检索可独立使用” |
| D02 发送前预览，约1分钟 | 切“资料问答”，明确选择M-短课件，输入准备好的概念/对比问题，点击预览；先不确认 | 能看到模型、目的地、问题、实际片段、覆盖和字符数；没有生成任务 | 截图S02：预览。说明原件/图片不自动发送，仅发送确认的正文与选中笔记 |
| D03 问答与回源，约2分钟 | 勾选同意并确认生成；等待结束，展开一条引用，点击回到原文 | 答案符合人工预期，引用摘录与原文一致，定位版本正确；不将定位正确说成解释绝对正确 | 截图S03：答案与引用；S04：回到原文。说明引用由服务端校验 |
| D04 学习报告，约2–3分钟 | 切“学习报告”，选择同一章节，填写学习目标和方式；可选N-个人笔记并明确确认。核对预览后生成；也可打开已保存的同设置报告 | 展示目标、知识点解释、重点/难点/考点及理由、例子/误区、自测和依据；补充笔记与原始课件引用区分 | 截图S05：知识点/理由；S06：例子、自测及来源。说明结果保留独立身份、模型和提示词版本 |
| D05 人工审阅与笔记，约1–2分钟 | 从报告进入标签审阅，修改一条重点理由；进入可编辑笔记草稿，再明确保存 | 报告原始结果保持；草稿内容和引用保留；进入笔记后可回源，刷新后已保存笔记仍存在 | 截图S07：审阅/草稿；S08：已保存笔记。说明AI不直接替用户认定事实，保存由M3完成 |
| D06 结果复用，约1分钟 | 回到AI学习，以完全相同问题、来源、笔记、模型和设置重新预览；出现匹配结果后选择直接使用 | 取回同一成功结果，无新生成任务；不能只凭页面快就声称节省了多少推理时间 | 截图S09：复用提示与结果。若输入有变化不匹配，按真实状态说明，不能现场改原问题 |

D01可以只演示检索返回来源，把离开AI页面的跳转留到D03，以减少导航次数。报告若过长，只展开一个代表性知识点与一个自测，不逐项滚动全文。前一案例的草稿保存完成后再切换。

## 五、非功能性案例：挑选2–3个现场演示，其余用截图/证据备查

| 编号/特性 | 操作与预期 | 注意与证据 |
|---|---|---|
| NF01 发送控制与隐私 | 只预览不确认，观察尚未生成任务；核对片段范围、平台地址，再确认后才派发 | 可与D02合并。没有发出模型请求的严格证据以任务/调用状态和已有MockTransport测试为准，不只凭没有答案 |
| NF02 可追溯与证据不足 | 先展示D03逐字回源，再提出该资料明确无法支持的问题，只选择M-短课件；结果应明确无充分依据 | 模型可能仍尝试回答，必须预演验证；若产出无支持答案，是待修问题，不能把任何回答都判通过。不强行制造伪引用或改程序 |
| NF03 长课件处理 | 选择M-长课件，提问后部或跨章节问题；预览应显示完整所选可提取正文与多批计划；查看处理中进度和统一答案引用 | 显式选资料与未选资料检索模式不同。展示末页依据，不能只以“400段/24万字”证明实际覆盖。分批不等于一次全部塞进模型上下文 |
| NF04 取消与恢复 | 用专门长任务演示排队/处理中取消；停止后续步骤，已完成检查点保留。对于已有可续跑失败任务，明确同意继续新窗口，核对成功步骤不重发 | 不在主案例半途中取消；任务完成太快时用排练截图。已发请求不能召回，取消不是退费或撤回远程数据。只有界面确实提供继续入口时操作，不把所有取消状态都说成必可续跑 |
| NF05 账户隔离 | A已有配置；在另一个浏览器会话登录B，B未配置时提示本账户未配置，不能借用A的Key；A仍可正常使用 | 不投屏密钥。更多越权尝试由临时账户自动测试说明；两个浏览器同一localStorage会互相影响，建议独立浏览器/隐私窗口 |
| NF06 配置修订与失效 | 用演示账户先预览，随后更换模型或更新配置；旧预览应拒绝派发/复用，要求重新预览 | 放在最后，避免打断其他案例。配置改变也可能影响历史复用资格；不是随便选择一个模型都能保证输出格式兼容 |
| NF07 错误处理与预算 | 展示已发生的超时/限流/格式错误记录，以及120秒窗口、调用数、授权最多2次结构修复和保留进度提示 | 不故意消耗到限流，也不要求现场等120秒。结构修复只针对符合条件的输出结构，不能修复伪引用或推测缺失答案；不要自动重试 |
| NF08 性能与资源 | 对一次固定输入记录预览耗时、实际生成耗时、字符数、批次数及模型；相同输入再演示复用 | 建议排练3次保留范围/中位数，但每次真实生成均需本人确认。服务商延迟和本机检索分别说明；不把模型端速度作为纯后端性能，也不写未经测量的加速比 |

可直接组合：10分钟主流程已经包含NF01、引用回源及结果复用；额外用约2分钟展示NF03的预览/历史进度和NF05。长任务实时等待、取消/续跑、错误记录作为老师追问时的备查内容。

## 六、可选跨模块案例：已确认真题标签

M4先准备真实、已确认来源的Q-真题及知识点到课件片段的有效人工映射，不能仅上传题库。普通题库即使已核验，也不会自动变成真题。先确认来源/年份等元数据，再按M4流程确认身份。

用有关课件生成报告，只有实际引用与该知识点依据相交时才显示“已确认真题”。生成内容未引用对应片段时不出现标签不一定是错误，不应随意放宽判断；选择合适目标预演。撤回身份/映射后，旧预览或复用须失效，历史保留生成时快照并提示依据状态变化。此流程先在临时演示课程验收，再决定是否作为加分展示；不要求现场真实调用多次。

## 七、关键技术：每项对应可见行为

| 层次 | 当前实现 | 对应展示及边界 |
|---|---|---|
| 前端 | React、TypeScript、Vite；组件状态、表单与轮询、草稿保护 | 范围选择、进度/结果、引用跳转、窄屏布局；共享路由/请求框架并非M2独立开发 |
| 服务端与契约 | Python、FastAPI、Pydantic、HTTPX | 预览/确认分离、严格请求与结构化输出校验、异步模型请求和错误分类；当前项目经HTTP接口接模型，不是网页直接携带Key调用SDK |
| 持久化 | SQLAlchemy、SQLite；Alembic管理团队迁移 | AIResult、RemoteQuery、ProcessingJob及已有AIResult私有检查点；结果/进度持久化，不依赖浏览器临时聊天历史 |
| 资料依据 | 消费M1有效版本/片段，引用位置和摘录服务端核验 | 当前账户/课程范围、精确引用与回源；本地关键词/中文切分检索，不宣称已实现向量库或语义RAG |
| 长资料 | 确认范围冻结；8000字符/32来源单元分批、逐批找依据后统一回答，报告分批保存 | 长问答不只取前几段；最多400原片段/24万字符。处理范围只含可提取文本，图片公式完整性需核对 |
| 任务与预算 | 持久worker、租约/取消保护、120秒确认窗口、显式新窗口续跑 | 原调用与结构修复共用预算，成功步骤不重发；无故障后的无限自动重试，也不是保证120秒内完成 |
| 结果复用 | 账户、课程、范围、问题、笔记、模型/修订与提示词等匹配 | 直接使用完整成功历史结果，不新派发生成；失效、失败和部分结果不能冒充完整命中 |
| 模型与安全 | 共享Provider；账户派生加密配置、多模型选择；引用与来源变化复核 | 不回退别人的Key，不把Key放前端存储/业务备份；模型地址和图片能力受限制。共享模型改造有其他成员参与 |
| 人工可控 | 报告标签审阅、笔记草稿、明确保存；真实/演示模式区分 | AI建议不自动成为教师事实；标记来源已核验不代表所有解释语义正确 |

## 八、PPT及证据如何组织

本任务只提供内容设计，不制作实际PPT。建议M2占6页左右，页数由队长总时长调整：

1. M2解决的问题与本人分工：基于本人课程资料复习，输出可核对的知识理解，而非无来源聊天。
2. 正常功能闭环：使用S01–S04，展示从原文到问答再回源。
3. 学习报告到笔记：使用S05–S08，展示解释、自测、人工审阅和保存。
4. 完整性与特色：长课件覆盖、检查点/明确续跑、结果复用；只展示实测成功的内容。
5. 非功能与关键技术：发送控制、账户隔离、预算错误、分批与引用校验的调用链。
6. 工作量及验证边界：引用本次代码量清单，分开专属逻辑/样式/共享集成；说明教师强调仍待上游接通、统一资料实测结果待填。

每张截图配一句“操作 + 可核对结果”，不要只放页面。表格记录至少包含案例编号、材料版本、问题、模型/配置、片段/字符/批数、预期、实际、耗时、结果、截图路径。记录失败与修复后的复测，不事先勾选全部通过。

## 九、统一资料确定后需要补的空位

- 课程、资料文件名和版本；短课件小节、后部片段位置。
- 问答Q1、跨章节问题Q2、资料外问题Q3及人工标准要点。
- 报告学习目标/模式、选中的个人笔记、希望展示的知识点与自测。
- 确认选用的模型、实际耗时、截图S01–S09与异常备查图。
- 真题来源与映射是否准备完毕，是否纳入正式现场展示。

只有这些内容确定并排练通过后，才能将本设计转成“验收通过记录”。
