## 解决的具体问题

首页此前把全部历史失败任务用于「检查资料处理」提醒，即使后来上传的新版本已正常解析/索引，旧失败记录仍可能留下提醒。本轮新增attention_materials，按每份资料的最新版本计算当前问题；历史failed_jobs和处理记录保留原义，首页不再将历史失败数当当前问题份数。

资料阅读页「资料检查」可按名称与检查类型查找当前课程最新版本，支持真实计数、每页12份、分页与刷新。每份卡片分别说明可用正文、解析、索引、兼容预览状态和最新任务次数；可直接打开原版本或明确恢复有剩余次数的失败/取消任务。恢复复用原任务UUID/预算，不另建一套后台或自动重建。

检查项可重叠；兼容预览异常不表示文本或原格式一定不可读。没有可用正文不冒称已OCR；已确认人工文本可补正文来源，但原解析失败仍如实显示。检查用于核对已有状态，不评估课件质量或宣称所有复杂版式都正确。

| 步骤 | 网站操作 | 应看到的结果 |
| --- | --- | --- |
| 1 | 上传Markdown和无正文PDF，等待处理记录结束 | Markdown有文本，PDF可查看原页但解析明确没有正文；三阶段状态分别显示 |
| 2 | 资料阅读→「资料检查」 | 默认只列需检查的最新版本；选择「全部最新版本」可核对正常资料。计数为资料份数，同一资料可有多个检查项 |
| 3 | 按名称查找、选择「缺少可用正文」→「打开版本」 | 打开对应不可变版本；若有未保存整理/阅读笔记，取消离开后原输入和编辑DOM保持 |
| 4 | 在扫描PDF阅读页人工补录文字，核对并确认；回检查窗口刷新 | 该PDF不再计为缺少当前正文，有可用正文数量更新；其真实解析失败仍保留，不伪装成原件提取成功 |
| 5 | 有失败/取消任务时查看次数，明确点击「恢复解析/索引/兼容预览」 | 原任务重新排队，次数在worker实际尝试时递增。原件确实没有文本时重试仍可能失败，应使用人工补录；到上限不再提供恢复按钮 |
| 6 | 仅用于验收：选扫描资料，为其上传一份自制UTF-8 Markdown文字版作为新版本；等待成功，再回检查和首页 | 当前只检查文字新版；旧扫描版本及失败处理记录仍在，首页不再因旧版本失败持续提醒。相同内容改名重传仍按原去重规则，不重置旧任务预算 |
| 7 | 从检查卡打开文字版，摘录为笔记，进入学习关联/知识点/练习/错题回源 | 准备好的原文可继续完整学习流程，旧引用不改指新版；状态检查与恢复不改笔记、原作答或成绩 |

步骤5中，已完成的任务不需要人为制造异常。若恰有排队/运行中的任务，可从原处理记录取消，再在资料检查中恢复；太快完成时保持原结果即可。索引无可用正文时应先完成解析或确认人工文字；没有新建索引任务或绕过次数上限的隐藏动作。

## 异常与权限验收

| 情况 | 正确结果 |
| --- | --- |
| 旧版本失败，新版就绪 | 当前问题数量归零，旧任务仍可在处理记录翻页查看；首页当前提醒清除 |
| 多条历史阶段任务 | 只展示当前版本每阶段最新任务，稳定按created_at/id选取；旧任务不冒充当前阶段 |
| 有标题/标签但没有有效正文 | 按实际非空白文件提取或当前已确认人工Chunk判断，标题/标签不代替正文 |
| 人工草稿、历史确认、撤回 | 草稿/历史确认/撤回不当作当前有效人工正文；旧引用仍按原Citation规则处理 |
| 解析正在排队/运行 | 显示处理中，不在尚未完成时提前诊断正文缺失；不根据耗时猜测worker卡死 |
| 恢复中的关闭/跳转 | 阻止关闭和导航，等待请求结束；原件/引用保持 |
| POST网络/503或401结果未确认 | 不自动重放；先重新核对任务状态，再按最新结果明确操作。401让出重登，重登不自动恢复任务 |
| 首次断网或GET失败 | 局部错误、明确重试；不清空阅读笔记。关闭/范围变化后的迟到响应无效 |
| 其他账户/已删除课程或资料/独立题库原件 | 服务端拒绝或不纳入；GET只读、不触发后台和模型任务 |
| 当前页因资料状态变化为空 | 明确提示并可回第一页，不把已加载条数冒充总数 |

## 实现与实际验证

GET `/api/v1/courses/{course_id}/material-health`在同一读快照授权/统计/分页，只读最新版本、有效正文存在性与本页最新三阶段任务。SQL不投影原文、文件路径、预览路径或租约；名称是字面查找。恢复仍由原POST `/jobs/{id}/retry`重新验证归属、阶段状态、并发任务、输入与次数预算。

无新表、迁移、依赖、模型调用或后台任务类型。前端复用统一transport/AbortSignal和公共Dialog，UI随资料工作区可用，按需读取；统一主色、适中字级、卡片阴影、宽窄布局和触控保持。首页仅切换当前提醒的数据依据，不清理历史任务。

后端最终全量460通过、2个私有样本跳过（157.92秒）；新增4项API风险测试覆盖旧失败/新版、正文与人工状态、归属/删除、分页/字面查找、SQL无正文路径租约投影与GET零写入、原任务恢复/预算和恢复后就绪。前端26文件167单元通过，新增首页历史提醒回归；TypeScript/生产构建及相关Ruff通过。人工补录专项首次因样例提前置预览失败触发原有409，调整测试顺序后7项相关回归及全量通过，没有放宽补录保护。
