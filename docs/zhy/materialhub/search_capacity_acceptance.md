## 本轮解决的问题

原搜索固定截取50条，前端下载课程全部笔记后筛选，结果只取正文开头导致长文真实命中不可见。本轮新增[公共契约](../../contracts.md)规定的两个服务端分页入口；M1材料保持FTS5/BM25与版本/归属过滤，M3仅新增只读检索适配器，正文编辑、标签、知识库ZIP及M2/M4内部算法不重写。不改数据库，不新增依赖。

- 资料与笔记各自12条一页，显示真实总数，翻页可到达所有命中；资料分类/标签与最新/历史版本过滤不变，筛选选项只取目录聚合，不下载全部资料。
- 后端仅返回≤260个Unicode字符的纯文本命中摘要及高亮区间；前端按Unicode字符序号切片，用React文本节点/mark显示，不执行输入HTML。摘要偏移不是Citation偏移；点击仍按document/version/chunk UUID回源，保留原始引用校验。
- 笔记按题名或正文完整关键词包含查找、更新时间/UUID稳定排序，返回id/title/excerpt/updated_at，不传整份正文；不是FTS或语义搜索。材料旧数组API保留50条供既有调用方使用；超过100个去重检索词明确422，不静默丢词。
- SQLite legacy事务模式下显式建立只读快照，计数与页数据一致。并发删除笔记时同次请求保持旧快照一致，下次读取即撤权；跨页期间有更新可能改变结果，不承诺冻结整个会话。
- 实测发现PPTX组合形状原来只读外层，组合内文字/表格遗漏。新增嵌套遍历，保持形状树顺序及原幻灯片定位；空幻灯片不让后续页号前移。既有不可变版本不重写，需要作为新版本重新导入才采用新解析。
- 笔记引用不可用时改成中性提示“来源当前不可用”，避免把人工补录撤回误称文件已删除。这是M3显示消费适配，不改变笔记正文。

## 容量与性能实测

命令：`.venv/bin/python scripts/verify_capacity.py --output /tmp/hustudy-capacity-final.json`。自制10课程、200份实际上传并经隔离解析/索引的Markdown、1000篇笔记、5000片段；测试结束临时数据清理，现有账户未访问。硬件只读记录为Apple M4 / 10逻辑CPU / 24GiB，macOS15.7.9 arm64、Python3.11.15、SQLite3.50.4；浏览器测试Node25.2.1。实际机器高于需求建议4核/8GB，不推定低配机器同样达标。
