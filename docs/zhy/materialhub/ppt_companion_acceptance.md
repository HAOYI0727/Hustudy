## 阅读页现在做什么

打开当前PPT后点击“AI阅读助手”，面板只围绕该不可变版本：总结设置→知识点与页码→笔记草稿。没有课程问答/学习报告模式切换、课程选材或跨资料选择；无需跳转AI学习页。默认纳入当前版本全部可提取文字，初始化失败不回退到全课程。历史也仅列课程最近20条中可确认只属于当前版本的报告，不混入包含其他课件的报告。

阅读视图与完整AI工作区分别呈现，共享发送会话、后端任务、预览确认、引用校验和笔记保存，以保持同一安全与数据契约。没有第二套模型接入、报告存储或自动生成流程；打开工具、切侧重点、查历史不调用模型。已有独立AI学习工作区继续承担课程范围问答/多资料学习。

| 功能 | 实际行为 |
| --- | --- |
| 全面梳理 | 先通读本次输入，沿页序归并同一知识点，解释概念/原理/条件/公式代码/关系/误区；不固定只列前3–12项 |

| 知识点页码导览 | 只读真实引用的当前版本active slide/page整数定位，逐页回跳；1/2/3压为“第1–3页”，1/3仍为“第1、3页” |
| 全文与部分范围 | 发送段数/字符数来自服务端coverage；部分/未知/跨批明确说明，不以引用页码数量证明全文完整性 |

单点引用按version_id/chunk_id/quote精确去重，不截断；无引用、失效或超过50条则明确拒绝。只整理笔记，不创建/修改Topic实体、教师标注、成绩或掌握状态。引用在保存时仍由原后端复核，界面先前显示有效不代替授权检查。

## 提示词与完整性边界

前端专用目标明确要求知识点组织、真实多页依据、原公式/代码条件、笔记层次及不可识别图像说明。服务端提示词版本提升为`zhipu-study-report-v7`，保留严格JSON结构、3–5项自测和逐项excerpt_id校验；要求读取所有已给输入、合并同主题、不只总结首页、不凭空补页。新版本复用沿原提示词版本一致性规则，旧结果可读但不冒充新提示词生成。

仍沿每次最多400片段/24万字符、原分批数量与输出预算。长课件每批独立生成，本轮没有增加跨批全文融合/去重调用。即使发送覆盖显示全部可提取正文，也不保证模型已准确归纳每个知识点；PPT图片、动画或未提取图表不自动成为依据。目录页/无文字页不凑造知识点，不把引用到某页当作整页已完整理解。

## 本人可这样验收

1. 用测试课程打开有正文的PPT，点击AI阅读助手。确认仍在资料阅读页，固定该版本，无课程问答/跨课件选择；打开不自动生成。
2. 分别点击“全面梳理/复习提纲/笔记写作”，查看提示词变化，可补自己的要求。预览时核对版本、实际文字覆盖、批次数与目的地；未同意不能发送。
3. 本人确认真实调用后，看总体总结、知识点页码目录和各知识点讲解，核对后部知识是否遗漏。若为分批/部分，不应显示已完成全文融合。
4. 找到多页知识点，核对每个页码按钮的原文。连续引用可以显示范围，间隔不能补出没有引用的页；历史没有coverage时明确无法核对。
5. 在目录点“写知识点笔记”或讲解处“整理此知识点为笔记”。确认只带入该知识点，审阅标签、修改标题并补自己的解释；全文例题/其他知识点仍保留在原报告。
6. 明确保存后打开知识笔记，检查标题、正文和原文引用。在来源片段“学习关联”应找到同一篇笔记；不自动生成练习或改变掌握。
7. 写草稿后收起/重开、切阅读笔记、取消跨版本离开，核对标题/正文仍在。开发协作模拟保存响应丢失时，标题/正文被冻结，重试仍一篇；不要求本人破坏日常网络/数据。

没有模型时，可用自制`materialhub_demo.md`的固定演示体验单点摘记/标题/真实保存；该演示不是对任意PPT的理解。真实PPT总结质量和页码完整性须本人核对。
