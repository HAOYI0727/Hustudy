## 结论与实施顺序

当前可用的核心闭环是题库导入校正、确认、随机抽题、冻结试卷、保存恢复、交卷、自评、错题和复习回源。真实扫描试卷的拆题覆盖与结构保真仍是明显短板；跨模块最明确的缺口是 M4 没有向 M2 提供可操作的真题身份确认入口。

建议顺序：①扫描拆题的覆盖和公共条件保护；②试卷/答案配对及真题身份；③补弱状态口径；④统计查询、页面会话和文档整理。不要把 OCR 任务 SUCCEEDED 或现有回归通过当成整卷内容验收。

## 1. 优先级高：扫描卷编号与公共条件可能丢失

**已复现。** 私人计组 ZIP 含10份PDF、共86页，均无可提取文本，每页有扫描图。10份原件经真实API成功上传，普通文本解析状态全部为FAILED；扫描检测接口正确返回全部页待OCR。这种文本失败应解释为“扫描件待识别”，不宜让用户误以为原件损坏。

对其中一份8页试卷运行了实际本地OCR（非模型替身），任务SUCCEEDED，但只形成11条解答题草稿，题号为`1,1,1,1,2,2,2,3,3,3,4`。与原页视觉核对后，中文大题、括号小题及跨页公共条件未被完整组织。所有11条均有`import_warnings`和审核用`source_images`，但没有作答用`illustrations`；这不是“没有任何警告”，也不能把审核原图当作作答插图已完整保留。未人工确定全卷正确题数，不宣称识别率。

代码原因之一可确定性复现：[bank_parser.py](../../backend/app/services/bank_parser.py)的START只匹配以数字开头的题号，GROUP只认“题目N/大题N”。当中文大题和`（1）`小题与后面的`1.`混用时，首次数字题号前的整段未进入任何题目跨度。用自制文本验证：

```text
一、公共条件甲。
（1）说明第一小题？
（2）说明第二小题？
二、公共条件乙。
1. 说明第三小题？
2. 说明第四小题？
```

当前仅返回第三、第四小题，前两小题和公共条件未保留。这个问题不依赖OCR质量，也不限于私人样本。

建议：先在公共契约定义“大题/子题/公共条件/续页”的可确认草稿结构，再支持中文序号、括号序号和OCR常见变体；题号只作显示，UUID保持身份。增加原文覆盖检查，将无法归属的前缀、段落、表格列为待处理，不静默丢弃。图表继续保留“审核原图”和“作答插图”的区别，必须经用户裁剪并确认不含答案后才进入作答。由M4实现，M1解析器保持只读适配。

验收应覆盖混合题号、跨页同题、重编号、图表、无题号页和答案污染；核对所有原始页能追溯到题目或明确的未处理区域，而不只断言任务成功、题数大于零。

## 2. 优先级高：独立答案文件没有配对闭环

**附件形态已确认，能力缺口由代码核查确认。** ZIP包含五组同年份的试卷/答案文件。当前[bank_archives.py](../../backend/app/services/bank_archives.py)按独立文档上传，后续也是逐文件识别；没有“把答案卷对齐到已存在试卷”的确认事务。当前解析器的答案附录支持也不能替代跨文件配对。

建议增加导入预览中的“试卷 / 答案 / 题解混合资料”角色及候选配对。文件名/年份仅用于建议，用户确认才成立；题号、章节、题型联合核对，不按“第1题”跨大题盲配。未匹配、重复匹配、不同卷别、未知答案单列，不能补造。答案附件不应被误算为第二份独立历年样本，也不能直接把含解答的整页作为考生插图。对已有试卷只更新本次确认的答案草稿，不重写历史试卷/成绩。

年份目前是上传表单共用值；多年份ZIP宜逐文件显示建议年份并确认，避免全部未知或错误共用一年。这属于待定义的新导入能力，不是本轮已经实现的功能。

## 3. 优先级高：M4 → M2 真题身份写入断点

**代码核查及API验证。** [exam_report_evidence.py](../../backend/app/services/exam_report_evidence.py)的自动读取要求：

```json
{"exam_identity":{"kind":"past_exam","confirmed":true}}
```

同时仍需题库/题目已确认、知识点映射`selection_reviewed=true`及有效课件引用。[BankMetadataEdit](../../backend/app/schemas/exams.py)和[metadata接口](../../backend/app/routers/exam_analysis.py)只接受年份、卷别、来源、重复代表卷等字段；实际提交上述身份字段返回422。全仓搜索未发现M4写入该身份的业务入口，已有M2测试直接在隔离数据库写入该值，不能证明用户界面可走通。

影响：用户即使核验题库和课件关联，普通流程仍不能让M2报告自动得到“已确认真题”依据。既有[gcx交接](../gcx/handoff_2026_10_24.md)也明确记录了这个上游缺口。

建议M4增加明确的“普通练习 / 本人确认历年真题”身份设置、来源说明及撤销，沿用账户/课程权限、元数据revision和进行中作答限制。身份变化纳入预览/统计/依赖指纹；M2按原只读适配消费，不从标题或年份猜身份。M4+M2联合验证普通题库排除、真题命中、撤销后旧预览拒绝和历史失效提示；若纳入课程包，也要验证导入后身份语义和UUID映射。无需先恢复AI出题。

## 4. 优先级中：历史错误与当前掌握口径应分开展示

**已复现。** 自制选择题首次空交卷后，缺口矩阵为`needs_review / judged_count=1 / error_count=1`。随后该错题重做正确，每日进度为`completed=1 / done=true / remaining_ids=[]`，重新读取缺口矩阵仍为原三个值。

[exam_analysis.gaps](../../backend/app/services/exam_analysis.py)只读ExamAttempt初次判定；[mistake_progress.mastered_since](../../backend/app/services/mistake_progress.py)已经实现重做和复发的当前状态，[exam_source_learning.py](../../backend/app/services/exam_source_learning.py)回源卡片也使用它。因此历史错误次数正确保留，但用户在不同页面看到的状态含义不够统一。

建议保留历史错误/首次正确率，另加“当前待复习数量、最近重做结果、复发状态”。复用M4既有只读事件适配，供M1课件关联、课程总览和M4矩阵共同消费。一次复习计划完成仍不能直接视为答对，保持日程完成与掌握独立。不要用重做结果覆盖原成绩，也不要简单将累计错误归零。

## 5. 优先级中：统计查询与目录可做有界优化

**静态核查发现，未做性能基准。** [exam_analysis.inputs/gaps](../../backend/app/services/exam_analysis.py)会加载课程题库和全部已提交作答；gaps对标签逐别名调用资料/笔记/图片检索，又在作答题目循环内反复调用`topic_tree.expand`。标签、历史卷数和作答增多后，查询及反序列化成本会放大。不能据此声称已测得性能故障或提升百分比。

建议先测同环境SQL次数与耗时，再预计算一次标签后代集合/合并重定向、按当前标签批量投影必要的判定字段，候选检索按需展开与真实分页；不要以只取“最近N份作答”冒充完整统计。保留统计快照、STALE及既有归属/来源撤销语义。

## 6. 优先级中：M4页面对齐其他模块的会话保护

**静态风险，未复现越权。** [BankAnalysis.tsx](../../frontend/src/features/exams/BankAnalysis.tsx)的异步`load`对切课/卸载没有统一的迟到结果丢弃机制；应仿照M1/M3按账户、课程和请求代次校验后再写界面状态。[BankPractice.tsx](../../frontend/src/features/exams/BankPractice.tsx)仍多处直接操作localStorage；建议统一账户UUID+课程的键及存储失败降级，避免服务器抽题/开始已成功、浏览器存储失败时被展示为整个操作失败。

服务端已有归属校验，这不是已证明的数据泄露；需要补快速切课、换号、慢请求返回、localStorage抛异常以及401不重放的专项验证。
